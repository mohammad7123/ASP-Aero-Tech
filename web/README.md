# ASP Aero Tech — public website (`web/`)

Cinematic marketing site for ASP Aero Tech: a scroll-driven 3D flight through the home page, an exploded view of the aircraft, interactive 3D product turntables, a dot-matrix globe, and a HUD design language — built to stay fast and accessible.

| | |
|---|---|
| Framework | Next.js 16 (App Router, Turbopack) + TypeScript, React 19 |
| Styling | Tailwind CSS v4 (design tokens in `src/app/globals.css`) |
| 3D | three.js + React Three Fiber 9 + drei 10 |
| Motion | GSAP 3 + ScrollTrigger, Lenis smooth scroll, CSS |
| Data | The existing ASP API (`artifacts/api-server`) with bundled fallbacks |

This app sits next to the existing Replit monorepo. The **admin console** (the `/admin` route of `artifacts/aps-aero-tech`) and **API server** (`artifacts/api-server`) are unchanged — this site reads products, contact details, socials, careers and blog posts from that API and posts contact-form inquiries into the same database. It deliberately lives **outside** the pnpm workspace globs (`artifacts/*`, `lib/*`, `scripts`) and uses npm, so Replit's frozen-lockfile installs are unaffected.

## Quick start

```bash
cd web
npm install
cp .env.example .env.local   # optional — see "Environment variables"
npm run dev                  # http://localhost:3000
```

| Script | |
|---|---|
| `npm run dev` | Dev server (Turbopack) |
| `npm run build` / `npm start` | Production build / serve |
| `npm run lint` | ESLint (`eslint-config-next`, React Compiler rules) |
| `npm run typecheck` | `tsc --noEmit` |

Node 20.9+ is required (Node 24 tested).

### Environment variables

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Canonical origin for metadata, sitemap, Open Graph and JSON-LD. Falls back to Vercel's production domain, then `http://localhost:3000`. |
| `ASP_API_URL` | Origin of the existing API server **without** `/api`, e.g. `https://asp-aero-tech.replit.app`. Server-side only — never exposed to the browser. |
| `ASP_REVALIDATE_SECONDS` | How long API-backed pages are cached before revalidating (default 300). |
| `NEXT_PUBLIC_DRACO_PATH` | Optional self-hosted Draco decoder path for GLB models (default: Google's CDN). |

Without `ASP_API_URL` the site renders entirely from `src/content/*`. The contact form then **logs** inquiries to the server console in development and shows an error in production (so leads are never silently dropped).

## How the home page works

1. **Boot loader** (`fx/BootLoader.tsx`) — server-rendered so it paints instantly. Progress reflects real readiness (fonts, window load, and the 3D world's first frames via `lib/boot.ts`), bounded between 1.4 s and 3.8 s. An inline `<head>` script skips it on repeat visits in a session and for reduced motion.
2. **World stage** (`home/Flight.tsx`) — a fixed canvas behind the hero and journey sections. `FlightExperience` uses ScrollTrigger to publish scroll progress into `lib/flight.ts`, and measures each `[data-flight-segment]` section so the 3D choreography adapts to any screen height.
3. **Scene** (`three/world/WorldScene.tsx`) reads that progress every frame (no React re-renders) and maps it to:
   - a position along the flight curve (`world/path.ts`) — take-off, cruise, a hold at the anatomy waypoint, then the city crossing;
   - drone attitude (pitch into speed, bank into turns, pointer-follow tilt in the hero);
   - an orbiting chase camera (keyframes per section: hero → climb → about → anatomy close-up → control → end);
   - the **exploded view**: parts separate during the anatomy section and reassemble before it ends. Labels are plain DOM, positioned each frame from 3D anchors (`lib/anatomy.ts`).
4. Shaders are compiled with `renderer.compileAsync` before the first frame, the render loop **stops** once you scroll past the flight, and the pixel ratio steps down automatically if the frame rate drops (max 2).

### Performance tiers (`lib/device.ts`)

| Tier | Who | What renders |
|---|---|---|
| `high` | desktop / capable GPUs | full scene, DPR ≤ 2 |
| `low` | phones, tablets, ≤4 cores/GB | fewer particles/buildings, no clouds, DPR ≤ 1.5, mobile camera framing |
| `static` | reduced motion, Save-Data, no WebGL, software renderers (SwiftShader/llvmpipe), ≤2 GB devices | **no WebGL** — SVG blueprints, CSS radar, static backdrop |

Force a tier for testing with `?gfx=high`, `?gfx=low` or `?gfx=static`.

> **Lighthouse note:** headless Chrome and PageSpeed Insights usually render WebGL in software (SwiftShader), which this site treats as a low-end device — so lab runs measure the static path. Profile the 3D path on real hardware with the Chrome DevTools Performance panel (or Lighthouse inside your desktop Chrome, which uses your GPU).

## Editing content

Everything visible lives in `src/content/`:

| File | Contents |
|---|---|
| `site.ts` | company name, taglines, nav, inquiry interest options, hero/CTA copy, **fallback** contact details, feature switches (`bootLoader`) |
| `products.ts` | the 9 platforms (mirrors the admin catalogue), airframe labels, 3D model per product, `heroModel` |
| `services.ts`, `industries.ts`, `about.ts` | page copy, transcribed from the existing site and the "About ASP Aero Tech" document |
| `highlights.ts` | stats, globe pins/arcs, testimonials, exploded-view part copy, training modules |

**When the API is connected**, these come from the admin console instead and update within `ASP_REVALIDATE_SECONDS`:
products (name, description, image, specs, features, categories), contact email/phones/addresses, WhatsApp, socials, Google Analytics ID, chatbot, careers and blog posts. New products added in the admin get pages automatically; pick a 3D preset for them in `products.ts` (otherwise one is inferred from the name).

Intentionally left for you to fill with verified information:

- **Stats** — derived from published specs only. Add operational figures (flight hours, aircraft delivered, pilots trained) to `stats` once verified.
- **Testimonials** — the section renders automatically when `testimonials` has real, attributable quotes.
- **Globe pins** mark operating *environments*, not deployments; add real sites with `kind: "site"`.
- **Contact fallbacks** in `site.ts` are empty because the real values live in the admin console.

## Swapping in real drone models (GLB)

Every model is procedural today (no downloads), defined by presets in `components/three/models/presets.ts`. To use a real model:

1. **Optimise** the file (Draco geometry + WebP textures):
   ```bash
   npx @gltf-transform/cli optimize input.glb public/models/vtol.glb --compress draco --texture-compress webp
   ```
   Aim for < 2–3 MB per model; the hero model should be the lightest.
2. **Point the product at it** in `src/content/products.ts`:
   ```ts
   model: { kind: "gltf", url: "/models/vtol.glb", preset: "vtol-quadplane", scale: 1, rotation: [0, Math.PI, 0] }
   ```
   `preset` is still used for the SVG blueprint and as the stand-in while the GLB downloads. For the home-page drone, change `heroModel` the same way.
3. **Orientation & scale:** forward is **−Z**, up is **+Y**, roughly 2.5 units across. Adjust `scale` / `rotation` / `position` rather than re-exporting.
4. **Spinning props:** name propeller nodes `prop…`, `propeller…` or `rotor…` — they spin around their local Y axis automatically.
5. **Exploded view:** name parts `part_canopy`, `part_fc`, `part_battery`, `part_gps`, `part_gimbal`, `part_gear`, `part_motor_1…`, `part_prop_1…`, or add glTF extras `{ "explode": [x, y, z] }` to any node. Offsets are applied in the node's parent space, so keep explodable parts as direct children of the root. Labels follow the procedural hero's anchors; add your own anchors if the geometry differs.
6. **Self-hosting Draco** (optional): copy `node_modules/three/examples/jsm/libs/draco/gltf/*` to `public/draco/` and set `NEXT_PUBLIC_DRACO_PATH=/draco/`.

## Accessibility & SEO

- Semantic landmarks, skip link, visible focus rings, ARIA tabs for the model switcher, `<dialog>` for the lightbox and cookie preferences, labelled form fields with inline errors.
- All 3D is decorative (`aria-hidden`); every scene has an HTML equivalent. Telemetry is simulated and marked decorative.
- `prefers-reduced-motion` disables WebGL, smooth scrolling, the loader, the custom cursor and all animation.
- Primary buttons use dark text on saffron (white on `#F47E20` fails WCAG contrast).
- Metadata API with per-page titles/descriptions/canonicals, generated Open Graph image, `sitemap.xml`, `robots.txt`, web manifest, and JSON-LD for Organization, WebSite, Product (each platform), ItemList, BreadcrumbList, BlogPosting and JobPosting.

## Deploying to Vercel

1. Push the repository to GitHub/GitLab/Bitbucket.
2. In Vercel: **Add New → Project →** import the repo.
3. Set **Root Directory** to `web`. Framework preset: **Next.js** (auto-detected). Install/build commands: defaults (`npm install`, `next build`) — Vercel picks npm from `web/package-lock.json`.
4. **Environment variables** (Production and Preview):
   - `NEXT_PUBLIC_SITE_URL` = your domain, e.g. `https://www.your-domain.in`
   - `ASP_API_URL` = the deployed API origin (the Replit deployment that also serves the admin console)
5. Deploy, then add your custom domain under **Settings → Domains**.
6. The API is called server-side only, so no CORS changes are needed. Uploaded product images are served from `ASP_API_URL/api/storage/...`; `next.config.ts` allows that host for `next/image` automatically at build time (redeploy if the API origin changes).
7. Content edits in the admin console appear within `ASP_REVALIDATE_SECONDS` (default 5 minutes) without redeploying.

Recommended after launch: set up Vercel Analytics / Speed Insights, and point the old site's public routes at this deployment (keep the admin console where it is).
